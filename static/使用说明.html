把经营问题问给数据

织见是一个面向纺织制造企业的经营分析平台。用一个例子了解它：经营负责人问“8 月赚了多少钱”，系统怎样把这句话变成一笔可以核对的账？

01　项目介绍

让业务人员用中文查数，让数字有口径可查

销售订单记录收入和成本，财务费用记在另一张表里。经营负责人只想知道一个月的经营利润，过去往往要请人导出两份报表，再确认月份、范围和公式。织见把这套查询流程做成工作台：业务人员提出问题，系统按他的岗位权限查数，返回结果；财务可以在指标中心用同一口径复核。

看现状 · 经营总览先看本岗位范围内的收入、生产或库存概况。
查数字 · 智能问数写清期间和指标，获取查询结果、单位和口径说明。
看变化 · 经营分析比较两个期间，把收入、成本、费用的变化拆开看，再汇总成报告。

当前是可在 Windows 本地运行的 MVP，内置 2026 年 3—8 月的模拟业务数据。MySQL 保存业务记录；Milvus 保存表、字段和指标的说明，帮助系统找对数据。演示环境没有连接真实企业 ERP。

02　工作流程

从一句问题到一笔账

2026 年 8 月的经营利润是多少？
  1. 先理解问题。系统校验输入，规范问法，识别是查一个数还是需要多步分析，保留“2026 年 8 月”和“经营利润”。如果只问“那上个月呢”且缺少指标，先请用户补充。
  2. 准备表、字段和指标公式。明确的单表查询只提供必要的表结构。经营利润涉及订单和费用，系统要寻找相关表、字段与关联，并从指标知识库取得 FIN-005 的口径：销售毛利减期间费用，两边分别汇总。
  3. 生成并执行查询。把问题、表结构、指标口径统一交给模型生成 SQL，再检查只读操作、角色、区域和字段权限，检查通过后才交给 MySQL。即便用户问得出“利润”，也不等于他的岗位有权看成本。
  4. 返回数字和依据。全公司默认样本算出 287,590 元。用户可以看结果表，去指标中心核对计算期间和公式。这里的“经营利润”是项目的管理口径，并非税后净利润。
如果问题变成“为什么利润变了”？ 系统通过 Plan-and-Execute 先列子任务，例如分别比较两个期间的销售毛利和费用。每个数据查询都复用上面的流程，最后依据各步结果汇总报告。数据能说明哪项变化贡献最大；没有证据的业务原因仍需人工核实。
03　业务操作

第一次用：先问、再验、最后分析

  1. 登录经营总览。 在已部署的电脑打开经营工作台，演示账号 executive，初始密码 demo123。销售、生产、仓储登录后看到的菜单和数据范围不同。
  2. 点「智能问数」，提交下面的问题。
    2026年8月经营利润（管理口径）是多少元？仅返回这个指标。
    等待任务完成，查看结果表和处理进度。默认样本的全公司经营利润是 287,590 元。不是税后净利润，也不是这家企业的真实业绩。
  3. 点「指标中心」，独立核对。 搜索 FIN-005 → 点击「经营利润（管理口径）」→ 选 2026-08 →「计算」。它按登记公式计算，不依赖模型猜公式：先算已交付订单的销售毛利，再减同期间费用。与上一步核对时要用同一账号、期间和单位。
  4. 点「经营分析」，问一个需要拆解的问题。
    比较2026年7—8月与5—6月的经营利润，分别列出销售毛利和期间费用的变化，说明哪一项影响更大。
    打开处理进度和各步骤结果，对照数字读结论。「个人报告」可回看近期任务，已完成的分析可下载报告。每次提交是独立问题，不能只写“那上个月呢”。

换个岗位，看看权限差异

sales_east 是华东销售经理，可查授权区域销售数据，不能看销售成本或毛利。production 看生产，warehouse 看库存，finance 看财务指标。以上为本地演示账号，初始密码相同。只有 admin 能进入「账户管理」「审计记录」「模型设置」。

附录 A　数据来历

屏幕上的数字，究竟从哪来？

安装时由 Python 按固定随机种子生成，没有下载企业订单，也没有让大模型临时编数。问数读的是数据库。默认新库有 52 张业务表、1,461 行业务数据，以下数量不含账号和审计记录。

数据生成方式与规模在系统里的作用
核心交易与主数据scripts/seed.py：客户 6、产品 6、供应商 3、订单 540、生产批次 108、采购 108、库存快照 108、费用 54，共 933 行。存 MySQL。每月 90 条销售记录，用于收入、交付、利润和库存核算。
扩展业务记录scripts/seed_extended.py：44 张表各 12 行，共 528 行，包括出货、质检、停机和盘点。存 MySQL。用于验证跨表关联和权限，并非完整可勾稽的真实 ERP 流水。
指标知识textile/metric_catalog.py 编写 32 条指标：公式、单位、过滤条件、时间字段、适用岗位。发布到 MySQL 的 metric_registry。回答“怎么算”。例如确认销售收入按实际交付日，不按下单日。
检索向量一张表说明、一条字段说明、一条指标定义分别是一份文档：52 + 304 + 32 = 388 条，256 维。存 Milvus 集合 textile_schema_metrics_v2。用于找相关表、字段和口径，不存订单明细。
为什么能分析出成本变化？ 脚本刻意把 7、8 月前两款全棉产品的模拟单位成本乘以 1.25，并把对应生产批次的疵损比例从 2.5% 设为 7%。这是为了演示变化可被追踪，不是对真实公司的判断。
附录 B　维护模拟数据

我要改的是一笔记录，还是所有人的计算口径？

目的改哪里怎样看见变化
改当前库里一笔费用用获准写入演示库的账号在 Navicat 改 finance_expenses.amount。先记下主键和原值；textile_reader 只能读。提交后用相同月份重算 FIN-005。例如 8 月费用增加 100 元，其他数据不变，全公司经营利润应减少 100 元。不必重建向量，旧报告不会改写。
让下次安装生成另一批数据改核心或扩展生成脚本中的月份、数量和金额规则，在隔离的新库验证。核心脚本检测 seed_version，扩展脚本只填空表。只重启或重跑脚本不会覆盖已有交易。
改变公式或时间口径改 metric_catalog.py，执行 uv run python scripts/publish_metrics.py。对照指标中心、智能问数和看板；看板有独立 SQL，改公式不代表所有看板自动同步。
新增表、字段或换数据期间迁移 MySQL 结构，更新目录、关联、岗位权限；结构说明变更后运行 uv run python scripts/build_index.py。更换期间还要更新实际数据、默认月份及展示文案。重新启动 API 与 worker，前端改过则重新构建；分别用有权和无权账号验证。

独立查看：Navicat 连接 127.0.0.1:3318，库名 textile_insight；只读账号的密码见该部署本地 .env 中的 TEXTILE_DB_PASSWORD。可选向量管理台：先启动主平台，再执行 docker compose -f compose.tools.yaml up -d，打开 Attu，使用预设的 milvus:19530。数据库管理不在业务网页内。

附录 C　管理员操作

在另一台 Windows 电脑上运行

准备 Git、Python 3.12、uv、Node.js 22.12+（含 npm）、Docker Desktop（Linux 容器）和自己的百炼 API Key。先启动 Docker Desktop，确认 docker info 有 Server，再依次在 PowerShell 执行：

git clone https://github.com/Lemon1216yu/textile_insight_agent.git
cd textile_insight_agent
uv sync --locked
uv run python scripts/configure.py
docker compose up -d --wait --wait-timeout 180
uv run python scripts/seed.py
New-Item -ItemType Directory -Force artifacts | Out-Null
.\start.ps1

密钥在页面填写：打开工作台 → admin / demo123 登录 → 左侧「模型设置」→ 粘贴自己的百炼中国内地（北京）Key →「测试并保存」。看到“索引已就绪”后再问数。首次验证与建索引消耗少量模型额度。密钥不回显，不用每个用户各填一遍。

以后启动：.\start.ps1；停止应用：.\stop.ps1；应用和容器一起停止并保留数据卷：.\stop.ps1 -Infrastructure。保管好自动生成的 .env 和页面配置的 .env.model-key，不随手册分发。

附录 D　接真实业务

接企业系统，要另外做什么？

网页填 Key 只接通模型，没有接通 ERP，也没有自动导入企业数据。建议先选一个区域、一个月、一个指标（例如华东销售收入），按下列路径试点：

  1. 拿两份材料：IT 提供获准的只读接口、视图或脱敏样本及字段字典；财务提供同期间同区域的权威报表。
  2. 对齐一行的含义：如果一张订单分三次交货，按出货明细唯一键和实际交付金额入库，不能三次复制整单金额。同时约定退货、币种、税额和月份归属。
  3. 同步到独立分析库：源系统 → 暂存与去重 → 分析库 → Agent 只读查询。需按实际接口开发同步器及独立迁移流程，禁用演示填数。不要把这套演示启动脚本直接指向生产 ERP。
  4. 验收后再开放：财务报表、分析库 SQL、指标试算、智能问数四方对账；验证区域和成本字段权限。多步报告可能向模型发送 SQL 和结果行，先确定企业允许的数据范围。
附录 E　自查

常见问题

双击手册能看，为什么打不开工作台？

手册只是网页文件。127.0.0.1 指当前电脑；请在已部署并运行服务的电脑上打开。先看 健康检查，确认 mysql、milvus、redis、worker 均为 true。

指标试算成功，为什么问数失败？

试算直接按公式查库；自然语言问数还需要生成模型和可用额度。管理员检查「模型设置」，确认账号已开通生成模型和 Embedding。任务一直等待时看 worker 状态与 artifacts/worker.err.log。

为什么没有本月数据，或者销售账号查不到全公司利润？

默认样本只有 2026 年 3—8 月，请写绝对月份。销售岗位受区域与成本字段权限限制，要核对全公司经营利润请选择获准的经营负责人或财务账号。

刚改了数据，为什么还看到旧数字？

先确认改的是正确库、修改已提交，且账号、月份和指标一致。历史报告保留生成时结果；同一问数可能复用最长 120 秒缓存。先在指标中心重新计算，再提交新任务。
