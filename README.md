# 织见 · 纺织制造经营智能分析平台

一个可以在 Windows 本地运行的 ChatBI MVP。业务人员用中文提问，系统在账户授权范围内查询 MySQL，并解释指标；需要诊断的问题则由 LangGraph 拆成多个查询后汇总。公司、岗位和数据均为模拟配置，样本期间为 **2026 年 3 月至 8 月**。

## 一次提问如何得到答案

以“2026 年 8 月的经营利润是多少”为例：

1. **理解问题。** 先校验输入、规范问法，再识别意图，保留原始期间、指标和筛选要求。
2. **找数据和口径。** 简单单表问题只注入轻量表结构；复杂查询动态检索相关表和字段、补充关联和指标公式。本例按 FIN-005 分别汇总销售毛利与期间费用，再相减。
3. **查数并解释。** 统一组装提示词生成 SQL，通过只读、表、字段和区域权限检查后查询 MySQL，返回结果及依据。需要多步分析时，先拆子任务，各查询复用这条链路，最后汇总成报告。

## 第一次怎么用

已部署时打开[本机工作台](http://127.0.0.1:8018/)，用演示账号 `executive / demo123` 登录。在「智能问数」提交上面的例题，再到「指标中心」搜索 `FIN-005`、选择 `2026-08` 并计算。默认样本的全公司结果应为 **287,590 元**。想看利润变化，再到「经营分析」比较两个期间的毛利与费用。

[打开完整使用手册（本机服务）](http://127.0.0.1:8018/static/使用说明.html) · 下载后也可以双击 [static/使用说明.html](static/使用说明.html) 离线阅读。数据维护与 ERP 对接另见[数据指南](docs/DATA_INTEGRATION.md)。

## 从零开始

准备 Git、Python 3.12、uv、Node.js 22.12+（含 npm）和 Docker Desktop（Linux 容器）。先启动 Docker Desktop，确认 `docker info` 能显示 Server。模型生成和向量化需要可用的百炼 API Key 和模型额度。

在 PowerShell 中执行：

```powershell
git clone https://github.com/Lemon1216yu/textile_insight_agent.git
cd textile_insight_agent
uv sync --locked
uv run python scripts/configure.py
```

配置脚本生成本地数据库密码和签名密钥。**模型 API Key 不用写配置文件，可以等网页启动后再填。** 保留生成的 `.env`，不要分享或提交。

首次初始化基础业务表与演示账户，再启动平台：

```powershell
docker compose up -d --wait --wait-timeout 180
uv run python scripts/seed.py
New-Item -ItemType Directory -Force artifacts | Out-Null
.\start.ps1
```

启动脚本会迁移账户和指标表、填充扩展数据、检查 Milvus 索引，按需构建 Vue 前端，并在后台启动 API 和任务 worker。首次建立索引会调用 Embedding API。启动完成后打开 [经营工作台](http://127.0.0.1:8018/)，或访问 [健康检查](http://127.0.0.1:8018/api/health)，确认 mysql、milvus、redis、worker 均为 true。

首次打开网页，用 **admin / demo123** 登录 → 左侧 **模型设置** → 粘贴自己的百炼 API Key → **测试并保存**。此按钮验证生成模型与 Embedding，并在需要时建立索引；看到“索引已就绪”即可使用问数。只有管理员能配置，普通用户共用本部署的额度。密钥加密保存在本部署的 `.env.model-key`，不回显，不需要重启。环境变量和旧版 `.env` 配置仍可用，页面配置优先。本地演示账号不要直接用于公网部署。

如果首选生成模型不可用，可在本地 `.env` 中设置下项，再重启 API 和 worker。只填写你的百炼账号已开通的模型；备用模型不能代替 Embedding 额度。

```dotenv
TEXTILE_LLM_MODELS=qwen3.8-flash,kimi-k3
```

**部署验证（2026-11-10）：** 从 GitHub 干净克隆，使用独立 Python 环境、重新构建的前端以及全新 Docker 数据卷，实测建库、发布 32 个指标、建立 388 条向量、加载页面资源、登录和 worker 问数。使用具有模型权限的本机环境变量；未复制原项目配置或数据库。测试平台为 Windows + Docker Desktop，未在 macOS/Linux 上验收启动脚本。

## 第一次使用：用两条路径核对同一个数

1. 用 **executive / demo123** 登录。在「智能问数」输入：**2026年8月经营利润（管理口径）是多少元？** 提交后等待任务完成，查看结果和处理进度。
2. 打开「指标中心」，搜索 **FIN-005**，选择 **2026-08** 并点击「计算」。同一份演示数据的参考结果为 **287,590 元**。口径是当期销售毛利减期间费用，两者分别汇总。
3. 进入「经营分析」，输入：**比较2026年7—8月与5—6月的经营利润，分别列出销售毛利和期间费用的变化。** 查看子任务的数据与结论，之后可从「个人报告」回看。

## 日常启停及排查

在项目根目录运行：

| 操作 | PowerShell 命令 |
|---|---|
| 下次启动 | `.\start.ps1` |
| 改前端后重建 | `.\start.ps1 -Build` |
| 停止 API 与 worker | `.\stop.ps1` |
| 一并停止容器、保留数据库卷 | `.\stop.ps1 -Infrastructure` |
| 查看容器状态 | `docker compose ps` |

页面打不开时，先看 Docker 的 Server 是否就绪，再查 `artifacts/api.err.log`；任务一直等待则查 `artifacts/worker.err.log` 和健康检查的 worker 字段。若指标试算有结果但智能问数失败，检查模型密钥、可用模型和账户额度。健康检查通过不代表云模型一定可用。

## 数据、链路与验收

- MySQL 有 52 张模拟业务表；指标主数据有 32 条。Milvus 中的 388 条向量按 **52 张表说明、304 条字段说明、32 条指标定义**组织，不存订单明细。Navicat 和 Attu 的连接步骤见[独立数据库查看指南](docs/DATABASE_GUIDE.md)。
- 查询先校验、改写和识别意图。单表简单查询注入轻量 Schema；复杂查询检索表、字段、关联路径及指标口径，再统一生成 SQL，经过权限与只读校验后执行。多步分析的查询子任务复用这条链路。
- 本项目是本地业务 MVP。历史评测成绩需与当次模型和版本一起解读；具体用例、限制及尚未验收项见[链路与验收记录](docs/CHAIN_CURRENT.md)。
